## 唯一目标拓扑

非 Foundation：

```text
210 -> 220 -> 230 -> {241 -> 242, 251 -> 252} -> 260 -> 210 -> 010
```

Foundation：

```text
210 -> 220 -> 241 -> 242 -> 260 -> 210 -> 010
```

- 非 Foundation 的 230 只输出一份有序操作闭包，241 与 251 共同消费。
- 241 生成绑定数据；251 生成不含业务数据的受限 Python ORM；242 只验证数据；252 只验证 ORM；260 在数据库副本中绑定、执行和回归。
- Foundation 不调用 230、251、252，不读操作闭包、不使用 ORM。260 使用固定、版本化、确定性的参数化 INSERT 编译器。
- 旧字段生成器、字段策略器、表级装配器和 registry 只可用于历史审计，不得进入 V5 运行链路。
- 独立 ODS 分类/资产/validator 从运行期废止；其结构语义迁移到正式跨表约束与带类型引用图，其事件顺序语义迁移到操作闭包。

## 图与 Foundation 决策

- 带类型图覆盖 74 表、1963 字段和 470/470 条正式多字段约束；人工队列 0。
- 图边按 `REFERENCE_PREREQUISITE / CONDITIONAL_DEPENDENCY / SAME_RECORD_COMPANION / STATE_SOURCE` 分层；ANY 提供者组保留组语义。
- 信贷分户账与借据表形成个人、对公两个互引 SCC。它们是事件产物，不得进入 Foundation；必须由事件事务和操作闭包处理。
- Foundation 初次空库最小范围是 17 表、18 条最小记录；数量仅用于最小可用世界，不是数据产量目标。
- 业务前对象/状态即使语义合格，也须有真实下游证据才可独立铺底；无下游的 12 表只按具体 profile 扩容；45 张事件产物表永远由业务事件负责。
