## 1. 使用本规范前先读什么

新会话或 Agent 在创建、复制、修改或写入任何文件前，依次阅读：

1. `AGENTS.md`；
2. `docs/codex_east_experience_memory.md`；
3. `config/v5-architecture.json`；
4. `config/v5-package-catalog.json` 与 `contracts/v5-runtime-packages.schema.json`；
5. `docs/architecture/V5双通路与Foundation架构.md`；
6. 本文；
7. 若处理约束资产，再读 `结构图/约束资产V1-字段多字段与对象明细状态通路交接.md`。

发生冲突时，治理 manifest 注册的 JSON/Schema 中的 Agent 名、包名、输入输出协议优先；同目录旧 Draw.io 与 V2 Excel 只作历史快照。本文只规定运行数据如何归档，不能自行改名或扩张 Agent 职责。

## 2. 总原则

1. **来源、过程、交付严格分层。**原始来源不被修改；候选、失败、待审和被回退成果留在过程层；只有当前可交付的最新成果进入交付层。
2. **交付层不可原地修改。**需要修改已发布资产或包时，从其 immutable identity（`artifact_id + version + content_hash`）创建过程层新尝试；验证通过后生成新版本交付物。
3. **代码与产物分开存放。**Agent/模块代码按职责归档；Agent 输出按业务对象（`qa_id`、`foundation_id`、`asset_version`）归档，不能按 Agent 目录堆放跨阶段包。
4. **旧工程不可作为 V5 的直接运行依赖。**可迁移的旧代码或旧资产必须先复制到过程层，登记来源、改造目的和验证结果；通过后才进入 V5 公共代码或交付层。
5. **正式数据库全项目仅一个。**只能是交付层中的 `east_formal.sqlite`；过程层可有候选 SQLite、沙箱 SQLite，但不能冒充正式库。
6. **所有 LLM 输出均属于过程产物。**必须保存输入、原始响应、规范化 JSON、模型/提示词版本、来源引用校验与重试记录，不能直接发布。
7. **每次重试最多 3 次。**超过 3 次仍无法形成可验证结果，必须进入明确问题的人工审核，不可无限重试。

## 3. 标准身份与命名

| 对象 | 标准身份 | 物理目录用途 |
| --- | --- | --- |
| 约束资产版本 | `asset_version`，例如 `CA-V1.0.0` | 固定某次可供 000 使用的 SQLite、视图和 manifest |
| question-SQL 记录 | `qa_id`，例如 `QA-000123` | 一条题目的事实、规格、SQL、事件、数据与回归血缘 |
| Foundation 铺底任务 | `foundation_id`，例如 `FDN-000021` | 一次基础对象/状态铺底的全套凭据 |
| 过程运行 | `run_id`，例如 `RUN-20260805-001` | 一次可复现执行的输入、输出、日志、缓存和报告 |
| 自动尝试 | `attempt`，例如 `attempt-01` | 同一对象的可重试候选，不覆盖旧尝试 |
| 资产/包 | `artifact_id + version + content_hash` | 业务血缘身份，不等于目录路径 |

目录名称可用于方便人工查阅，但下游程序引用上游包时必须引用不可变产物身份，而不是根据某个文件路径猜测最新版本。

## 5. 各顶层目录的准入规则

### 5.1 `00_治理与合同`

这里放“规则如何执行”，不放运行结果、业务数据、模型原始响应或个人题目产物。

| 子目录 | 应放内容 | 不得放内容 |
| --- | --- | --- |
| `架构快照` | V5 架构图副本、总体方案、已批准架构变更说明 | 临时草图、未讨论结论 |
| `包协议` | Agent 包 JSON Schema、字段字典、错误码、版本兼容规则 | 某个 `QA` 的实际包 |
| `提示词与固定码值` | 已验证 Prompt、枚举、模型配置、Prompt 版本说明 | API 密钥、原始模型响应 |
| `发布规范` | 发布门槛、人工审核规范、回退规范、审计要求 | 单次发布结果 |
| `资产目录与查询合同` | 000 目标目录、查询请求/结果协议、白名单视图定义 | 运行期 SQLite 数据库 |

### 5.2 `01_来源冻结层`

这里保存事实源和能够证明事实源未被篡改的材料。任何解析脚本都只能读取，不能回写原始文件。

| 子目录 | 应放内容 | 特别规则 |
| --- | --- | --- |
| `EAST原始材料快照` | `east材料` 的完整冻结副本 | 必须复制，而不是从旧路径运行时直接依赖 |
| `EAST模型快照` | `east模型` 的完整冻结副本 | 只可作为辅助推断证据，不能冒充监管原文 |
| `CoreBank分布参考` | 仅 `info_analyzed_non_empty_datetime_adj.xlsx` | 只作分布参考，不进入约束资产 V1 |
| `文件哈希与版本清单` | 文件清单、SHA-256、冻结时间、来源路径 | 每次新增/替换冻结源必须更新 manifest |
| `来源内容索引` | 文件-Sheet-行-单元格、段落、页码定位 | 不应改写原文，只增建索引 |
| `来源到目标映射` | 原材料部分到 000 目标/约束资产的映射与抽样示例 | 用于发现未使用材料，不直接作为事实源 |

### 5.3 `02_参考与旧版引入`

这里保存可参考但不能直接成为 V5 运行依赖的材料。

- `pilot实验与问题批示`：两个 benchmark、六个 baseline 的报告、逐条问题与人工批示必须完整保留。
- `外部基线与论文证据`：外部论文、复现实验、对比基线的证据；不能混入 EAST 监管事实。
- `旧版最终800交付快照`：只保留最后一个完整的 question、SQL、data 版本；不保留已确认无用的历史生成批次。
- `按需引入台账`：每次复制旧文件进入 V5 过程层时，登记原路径、复制日期、使用原因、改造任务、测试和最终去向。

禁止从本目录 import Python 模块、读取旧 SQLite 作为 V5 的运行期数据库，或把旧产物直接复制进交付层。

测试代码、测试夹具、验收问题和已经签发的验收报告均在此处。它不存原始来源，也不存未审的业务过程包。

- `约束资产与000验收`：字段、表、关系、码表、隐私、编码、未命中解释等目标问题；
- `question_sql验收`：事实保留、规格一致性、SQL 语法/Schema 与双审回退；
- `data与ORM验收`：242、252、260 的正反例；

## 7. 提升、回退与删除规则

### 7.1 从过程层提升到交付层

提升前必须同时满足：

1. 输入来源、上游包、代码版本和模型/Prompt 版本可追溯；
2. 固定 JSON/Schema、字段存在性、来源引用和内容哈希验证通过；
3. 本阶段规定的审核、人工裁决、硬编码校验和回归全部通过；
4. 不存在未解决的冲突、待审项、失效引用或无效字段；
5. 创建 manifest，并记录前一版本的 `supersedes_ref`；
6. 交付层中不存在同身份的可变覆盖。

### 7.2 回退

发现已交付版本需要调整时：

1. 不删除、不修改交付层旧版本；
2. 在相应过程目录创建新 `attempt`，在 manifest 中引用被回退资产；
3. 完成修复、测试、审核与发布门槛；
4. 生成新版本交付物；
5. 在发布总账中标记旧版本被替代，但保留可追溯读取能力。

### 7.3 删除

不得删除来源冻结、已发布资产、已发布数据库、发布总账、人工批示、pilot 报告、模型请求/响应审计凭据。过程层中的临时大文件仅在其 manifest、报告和哈希已经保留且不再承担复现责任时，才可按单独清理策略归档或删除。
