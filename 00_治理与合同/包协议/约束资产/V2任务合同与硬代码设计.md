# 约束资产 V2：三 Agent 任务合同与硬代码设计

## 范围

- Agent1（DeepSeek）：一条数据元说明的 E 列原文输入，输出语义单字段约束项。
- Agent2（DeepSeek）：一条字段结构材料及已挂载检核规则输入，同时输出单字段约束项与多字段候选；绝不输入数据元原文、Agent1 输出或格式列。
- 硬代码：唯一精确映射自然语言表/字段提及，生成原子多字段规则并判定表内或跨表。
- Agent3（DeepSeek）：一条已映射多字段规则输入，提炼 ODS 生命周期关系和约束控制计划候选；不生成 ORM、SQL、生产取值公式或写库计划。

## 任务输入与输出

| Agent | 每条输入 | 固定输出 | 明确排除 |
| --- | --- | --- | --- |
| Agent1 | 一个数据元的编码、中文/英文名和 **数据元说明 E 列**、精确 `source_refs` | `extraction_status` 与 `constraints[]`；约束项仅为 `ENCODING_RULE`、`CODE_DOMAIN`、`DEFAULT_VALUE`、`FORBIDDEN_VALUE`、`VALUE_RANGE`、`NULLABLE`、`PRIVACY_TRANSFORM`、`OTHER` | 格式列、PK、唯一性、字段关系、外部知识 |
| Agent2 | 一个字段的结构材料（不含格式）、备注、已挂载检核规则和来源 | `candidates[]`，分为 `SINGLE_FIELD`、`MULTI_FIELD`、`OTHER`、`UNRESOLVED`；单字段归入固定约束项，多字段保留自然语言参与字段、条件与要求 | 数据元说明、Agent1 输出、格式列、全库 Schema、答疑、外部知识 |
| Agent3 | 一个 `MAPPED_UNIQUE` 原子多字段规则、映射字段组、必要参与表字段上下文和固定生命周期定义 | ODS 分类、`ods_members[]`（角色为 `OBJECT/DETAIL/STATE`）、`object_context`、`constraint_control_plan` | 新增字段、ORM、SQL、生产取值公式、可执行写库计划 |

所有 JSON 均含任务身份和原文 `source_refs`。`NULLABLE` 必须使用 `YES/NO/UNSPECIFIED`，比较/引用关系的 `value` 必须使用 `range_description`。这些键和值均由 Python 强校验。

格式不由 LLM 输出。硬代码只按《规范附件3》“表格说明”的第 6--11 条解析 `Cn`、`C..n`、`I`、`I..n`、`Dw.d`、`F`，固定产出 `data_type`、`string_length_exact`、`string_length_max`、`integer_max_digits`、`decimal_max_fraction_digits`。无法匹配时标记 `UNSUPPORTED` 并人工审核；不会猜测或降级为 LLM 判断。

## 最终 Prompt

三份最终 Prompt 由 `pipeline.py` 的 `agent1_prompt()`、`agent2_prompt()`、`agent3_prompt()` 与 `response_contract()` 拼接。每次真实调用保存完整、不可省略的拼接文本为 `prompt.txt`，因此人工审阅以试跑目录中的实际文件为准，而不是以本设计文档的摘要为准。

共同 System Prompt：`不得补充、纠正或猜测输入之外的事实；只输出 JSON。`

关键判定指令：

- Agent1：仅看 E 列数据元说明；不确定输出 `UNRESOLVED`。
- Agent2：必须同时拆分单字段与多字段；未见第二个原文支持字段时不能伪造多字段；`table_mention` 仅在原文显式出现表名/表代码时填写，否则置空。
- Agent3：对象为 Foundation 铺底且仅引用，明细为事件 `INSERT`，状态为事件 `UPDATE`；数值等式或比较本身不足以成为 ODS，缺少角色证据时安全退出为 `NOT_ODS` 或 `UNRESOLVED`。对正向 ODS 输出固定枚举的约束控制步骤，例如 `EVALUATE_CONDITION -> READ -> BOUND/CHECK -> ALLOW`；每一步带 `gate`，明确无条件、条件为真或条件为假的分支，避免把“否则返回”误读为无条件终止。该步骤是候选控制顺序，不能作为 ORM/写库调用。

## 硬代码闸门

1. 格式列由硬代码按《规范附件3》“表格说明”解析；格式原文和解析结果不输入 Agent1、Agent2。字段未匹配 `Cn/C..n/I/I..n/Dw.d/F` 时为 `UNSUPPORTED` 人工审核。
2. 冻结输入、任务 ID、文件哈希、Schema、枚举和精确 `source_refs` 校验。
3. 表名/表代码、字段名/字段代码只能在冻结索引中精确唯一匹配；多字段 `table_mention` 为空时，硬代码以当前字段所在表作为唯一候选表，并记录 `DEFAULT_CURRENT_SUBJECT_TABLE`。
4. 任何零匹配、多匹配、映射后不足两个不同字段，产出 `PENDING_REVIEW`，不调用 Agent3。
5. 映射成功后，以参与字段、约束项、条件/要求和来源引用计算稳定 `atomic_multifield_rule_id`；单表为 `WITHIN_TABLE`，否则为 `CROSS_TABLE`。
6. Agent3 的正向 ODS 成员和控制步骤只能引用已映射字段；`NOT_ODS/UNRESOLVED` 是正确的安全退出，不视为失败。控制计划绝不直接生成数据库动作。

## 人工可审计输出

每次试跑均保存 `input.json`、完整拼接后的 `prompt.txt`、`raw_response.json` 和 `validated_output.json`。这些文件均在新的 `04_字段多字段与对象明细状态提取-V2/pilot/` 下；不创建、不修改发布资产。
