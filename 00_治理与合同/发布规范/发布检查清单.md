# 05_新版本交付层 发布检查清单

> 版本：V1
> 更新日期：2026-08-06
> 用途：每次向 `05_新版本交付层/` 发布新资产前，必须逐项检查并签署本清单。
> 本清单与 `发布清单.json`（manifest）配合使用；清单未通过则禁止合并 PR。

## 发布前检查

### 1. 来源追溯

- [ ] 所有交付文件的来源可追溯到 `01_来源冻结层/` 中的冻结文件或已批准人工决策
- [ ] 上游包引用完整：`artifact_id + version + content_hash`
- [ ] `source_ref` 精确到文件路径、Sheet、行号或段落

### 2. 资产身份与版本

- [ ] `package_id` 已分配且唯一（格式：`{TYPE}-{YYYYMMDD}-{NNN}`）
- [ ] `asset_version` 已按语义版本规则递增
- [ ] `supersedes_ref` 正确指向被替代的前一版本（如有）
- [ ] 文件物理路径与 `artifact_id + version + content_hash` 绑定关系正确

### 3. Manifest 完整性

- [ ] 所有交付文件列在 `发布清单.json` 的 `tracked_files` 中
- [ ] 每个文件的 `sha256`、`size_bytes`、`classification`、`origin` 正确
- [ ] `delivery_content_hash` 覆盖全部交付物
- [ ] Manifest 文件已放入 `05_新版本交付层/` 对应子目录

### 4. 安全扫描

- [ ] 安全扫描已执行，无阻断性发现
- [ ] 未包含 API Key、.env、Token、个人 SSH 凭据
- [ ] 未包含真实 CoreBank 数据（`.db`、`.sqlite`、`.WAL`、`.SHM`）
- [ ] 未包含 LLM 原始响应缓存（`deepseek_raw/`、`glm_raw/`、`model_cache/`）
- [ ] 安全扫描报告已保存至 `00_治理与合同/发布规范/安全扫描报告.json`

### 5. 验收与审核

- [ ] 对应阶段的审核全部通过（根据交付类型）：
  - 约束资产：单字段/多字段/ODS 提取校验通过 + 候选 SQLite 验证通过
  - question-SQL：确定性预审 + DeepSeek 独立审核 + GLM 独立审核 全部通过
  - data：数据验证（242）+ ORM 验证（252）+ SQL 回归（260）全部通过
  - Foundation：数据验证（242）+ 铺底回归全部通过
- [ ] 验收报告已签发并归档至 `06_测试与验收/`
- [ ] 不存在未解决的冲突、待审项、失效引用或无效字段

### 6. 人工批准

- [ ] 项目负责人或指定审批人已在 PR 中明确批准
- [ ] 批准记录包含审批人、日期和审批依据
- [ ] 若涉及规则不确定项，已获得人工裁决并在 Issue 中标记

### 7. PR 门禁

- [ ] PR 模板已完整填写（变更清单、验收结果、安全扫描、Manifest 哈希、审批依据）
- [ ] PR 通过所有必需的状态检查
- [ ] PR 审批数满足 branch protection 要求
- [ ] PR 将通过受保护分支合并（Squash merge），不直接推送 main

## 发布后确认

- [ ] 合并后 `05_新版本交付层/` 中的文件与 Manifest 记录一致
- [ ] `发布总账/` 已更新，记录本次发布的 `package_id` 和时间
- [ ] 如替代了旧版本，旧版本标记为 `superseded` 但保留可读

## 禁止事项

- 禁止跳过本清单任何一项直接合并
- 禁止在清单项目未通过时勾选
- 禁止修改已发布版本目录中的既有文件而不创建新版本
- 禁止将"待验证""待回归""审核失败"产物放入 `05_新版本交付层/`
- 禁止绕过 PR 模板直接合并包含 `05_新版本交付层/` 变更的 PR
