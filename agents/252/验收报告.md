## 结论

252 只读验证 251 `restricted_orm`（`v5.restricted-orm/v2`）的 Python AST、允许 API、导入编译、空数据空跑与对象—明细—状态顺序，通过后冻结同一 `code_hash` 并产出 `frozen_orm`（`v5.frozen-orm/v2`，发 260）；任一验证类型失败则聚合全部规则并产出 `orm_validation_failed_feedback`（`v5.orm-validation-failed-feedback/v1`，发 251）。全程不修改 ORM 代码/合同/元数据、不绑定数据、不跑 Gold SQL 回归、不写正式库、不承担独立 ODS。

## 固化边界

- 硬拒绝（ContractError，不产出反馈包）：传输/信封/内容哈希漂移、未知字段、Foundation 模式、上游 `blocked_manual`、结构/操作闭包引用不匹配、`code_hash` 与代码+执行合同+操作元数据不匹配。
- 五类 `validation_types` 失败聚合为反馈包，逐项定位 `operation_id`/表/对象：`static_ast`（AST+禁用构造/内建名+事务上下文）、`api_allowlist`（白名单+运行时版本+未批准调用）、`import_compile`（compile+受限命名空间 exec）、`empty_dry_run`（空 `{}` 零写入零副作用返回合法空报告）、`object_detail_state`（与 230 操作闭包 1:1 一致、依赖仅前向、UPDATE 状态步位于全部 INSERT 之后）。
- 通过输出完整继承 `orm_source_code`/`execution_contract`/`operations` 并保持 `code_hash` 不变；`validated_hash == code_hash`；`safety_precheck_report` 与 `sequence_validation_report` 为确定性 PASS 证据。
- 输入前后深比较零修改；`frozen_orm` 可复算（`validated_at` 默认继承来源 `created_at`，可显式覆盖）。
