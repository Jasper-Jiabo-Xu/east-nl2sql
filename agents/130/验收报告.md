# EAS-22 返工验收报告（实施侧）

本报告只记录脱敏 Fixture 的可复算结论；不包含运行期原始数据、SQLite、模型响应或密钥。

| 验收项 | 证据 |
|---|---|
| 两段 Schema 校验 | 130 传输包先执行 COMMON-ENVELOPE（含内容哈希、父引用、attempt），再执行 120/000/170/180/130 的业务 Schema。 |
| 130→000 合同 | `target_asset_types` 使用固定合法枚举；`previous_request_refs` 为不可变三元组。 |
| 可消费输出 | direct、indirect、partial/unobservable 均通过 EAST-OBSERVABLE-FACT-PACKAGE Schema；未知路径使用非空显式 sentinel。 |
| 回退 | 170/180 审核包精确绑定被审核 observable；扩张请求与 000 结果须 request_id、父引用、run/qa/trace/attempt 一致；第 3 次无命中生成 version+1、supersedes、attempt=3、`blocked_manual`。 |
| 事实—资产对应 | 000 Fixture 仅含原始 SQLite 行与固定 source_refs；130 候选层提出事实→本次记录索引→source_ref→代理表达，硬拒绝跨包、无记录、非本记录证据、空 table/field、重复/冲突候选；无候选降级。 |
| Manifest | 模板与 Schema 显式接收 issue_key，精确固化 `issues/{issue_key}/{run_id}/{attempt_no}`；跨 issue/run/attempt 和越界定位均被拒绝，并和本地 registry 对照。 |
| 下游 | 140 和 150 Stub 都验证传输包后消费输出。 |
| Agent | UUID、runtime、model、Skill、权限、并发与真实 task/run 引用由本轮 IMPLEMENTATION-HANDOFF 回写。 |

专项测试逐类覆盖：真实 000-shaped input→130 candidate validation→140/150 consumption、无候选降级、跨包/无记录/错证据/空表字段/重复冲突候选拒绝、170/180 回退、坏哈希、错绑审核包、attempt/run/qa/trace 血缘、manifest/registry 及跨 issue/run/attempt 拒绝。测试命令和计数以 handoff 中实际执行结果为准。
