# EAS-59 验收报告（实施侧）——242-数据验证agent 绑定 EAS-58 扩展约束服务

## 结论

242 只读验证 241 `bound_data`（`v5.bound-data/v1`）的单字段/数据元、表内多字段与跨表多字段/引用约束，通过后冻结数据内容哈希并产出 `verified_bound_data`（`v5.verified-bound-data/v1`，发 260）；任一验证失败则聚合全部错误并产出 `data_validation_failed_feedback`（`v5.data-validation-failed-feedback/v1`，发 241）。

本子 Issue（EAS-59）将 EAS-32 的 242 适配器从「adapter 自设 `total=len(records)`、`complete=True`、`field_rules_for_table` 占位 `ASSET_UNAVAILABLE`」升级为**绑定 EAS-58 已合入主线的权威完整约束查询面**：adapter 只消费 EAS-58 冻结的服务端回执 `v5.constraint-asset-query-result/v2`，沿服务端单次 HMAC 游标走到权威分页闭合；`total`/`complete`/游标/回执全部取自服务端，禁止 adapter 自设或自签。用真实 `ConstraintAssetService` + 脱敏 SQLite/JSONL/runtime-manifest fixture 重验 `build_constraint_asset_resolver → 242 → 260` 全链路，`>LIMIT` 遍历闭合、三 source 矩阵无缺失无重复，并保留裁决 A fail-closed 证据。

## 固化边界（fail-closed，裁决 A）

- **服务端权威完整性**：`total`/`complete`/游标/回执均来自真实 `ConstraintAssetService`；adapter 不覆写。分页未闭合（页链缺页/末页非 complete）→ `QUERY_RECEIPT_INCOMPLETE`；非真实服务 → `ASSET_QUERY_SERVICE_REQUIRED`；游标重放 → `ASSET_QUERY_CURSOR_INVALID`。
- **删条/替换正文**：SQLite 被删条或正文被替换 → 服务端 `_verify_sources` 重哈希 → `ASSET_PAYLOAD_HASH_DRIFT`（fail closed）。
- **来源/方法映射**：回执 `asset_version/artifact_type` 与查询方法映射（`EXPECTED_SOURCE_BY_METHOD`）不符 → `QUERY_RECEIPT_SOURCE_MISMATCH`；`artifact_id/content_hash` 与控制面不符 → `UNIVERSE_SOURCE_DRIFT`。
- **正文哈希**：服务端 `canonical_rule_hash` 逐项复算失败 → `RULE_CONTENT_HASH_DRIFT`；`resolve` 返回漂移内容 → `RULE_CONTENT_HASH_DRIFT`。
- **TRG 消费**：closure `from→to` 表对未被 `provider→consumer` 图边覆盖 → `GRAPH_REFERENCE_UNCOVERED`。
- **全集**：伪造空全集/错误来源哈希/跨 closure 重放/重复约束 → `UNIVERSE_SOURCE_SET_INVALID`/`UNIVERSE_SOURCE_DRIFT`/`UNIVERSE_CLOSURE_MISMATCH`/`UNIVERSE_DUPLICATE_CONSTRAINT`。
- 三模块按固定 registry 分派，聚合全部失败并逐项定位；确定性身份（`validated_at` 继承来源时间，报告不含墙钟）；输入深比较零修改；0-check `validated` 禁止。
