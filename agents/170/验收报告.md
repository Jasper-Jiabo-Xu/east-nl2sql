# EAS-26 验收报告（实施侧）——170-DeepSeek审核员agent

## 结论

170 独立消费 160 冻结的 `question_sql_pending_dual_review`（170/180 拿到完全相同的 `package_hash`），由 LLM 独立输出 `reviewer_id=170`、`decision`（`yes`/`no`）、六类固定 `error_types`、`error_details`、`evidence_refs` 与 `route_suggestion`，产出 `deepseek_review_result` 返回 110。硬代码只做合同与引用校验：输入 `package_hash`、输出 Schema、固定 error type、`reviewer_id=170` 与引用完整；LLM 不成为事实源。170 不读取 180 结论、不修改候选或上游包、不执行数据阶段。

## 固化边界

- 硬拒绝（`ContractError`）：传输/信封/内容哈希漂移、未知字段、`artifact_type`/`producer_id` 不符、`package_hash` 漂移、`review_round != attempt_no`、`precheck_report.decision != pass`。
- 语义报告硬校验：`reviewer_id != "170"` 拒绝；`decision` 仅 `yes`/`no`；`error_types` 仅六类固定枚举且不重复；`decision=yes` 时 `error_types` 必须为空，`decision=no` 时 `error_types`/`error_details`/`evidence_refs` 必须非空（证据不足拒绝 `EVIDENCE_INSUFFICIENT`）；全部错误必须路由到同一 `route_suggestion`（跨生产者冲突拒绝 `ROUTE_SUGGESTION_INCONSISTENT`）。
- 六类 error type 路由映射：`FACT_PACKAGE_ERROR→120`、`OBSERVABLE_MAPPING_ERROR→130`、`QUERY_SPEC_ERROR→140`、`QUESTION_SQL_ERROR/BUSINESS_EVENT_ERROR/QUESTION_FACT_OMISSION→150`。
- 三轮阻断：`decision=no` 且 `review_round=3` → 信封 `status=blocked_manual`；模型失败/非法输出经 `run()` 最多重试三次，三次仍失败返回 `decision=blocked_manual` 合法阻断，不伪造审核包。
- 170 与 180 隔离：不消费 `glm_review_result`（`artifact_type` 拒绝），180 的 `reviewer_id` 报告被硬拒绝。
