# V2 码值库：Agent1 V3 前置资产

## 资产边界

本阶段只构建审查用库，状态固定为 `review_only_not_released`：

- `code_reference_library_v2.sqlite`：附件4业务代码表及已有“国标与数据元绑定”审阅结果。
- `local_code_value_library_v2.sqlite`：数据元说明 E 列和数据结构备注 M 列的本地码值来源登记与未来落库骨架。

两库物理分离。当前 Agent1 V2 的 `CODE_DOMAIN` 自由文本不导入任一库，避免把未原子拆分的候选当作事实。

## 规范码表库

`code_reference_library_v2.sqlite` 由以下来源构建：

1. `规范附件4：金融资产管理公司监管数据标准化规范业务代码表.xlsx` 的目录和全部非目录 sheet。
2. `附件3附件2解析审阅报告.xlsx` 的“外部标准候选”“国标与数据元绑定”。

核心表：

- `code_table`：目录代码、名称、sheet、目录列出的参照规范和来源。
- `canonical_code_value`：按 `authority_key + code_components + 名称 + 说明` 去重后的规范码值实体。
- `code_table_value`：码表到规范码值的来源行连接；同一规范码值可被多个来源行引用，但只存一份实体。
- `code_value_alias`：多代码列（例如数字代码、字母代码）的查询别名。
- `data_element_code_table_binding`：审阅工作簿给出的数据元—外部标准—附件4码表绑定。

因此“同一编码在不同语义码表中”不会被误合并，而同一权威码表中的完全相同实体不会重复物理存储。

## 本地码值库

`local_code_value_library_v2.sqlite` 当前只登记来源：

- `local_value_source`：数据元说明 E 列与非空字段备注 M 列，均带精确单元格引用。
- `local_code_set` 与 `local_code_value`：为空，等待 V3 Agent1 输出的原子码值和 Python 校验后写入。

本地库绝不复制规范码表值。V3 遇到 `GB/T` 或已绑定 `CDxxxxxx` 时只能写 `CODE_TABLE_REFERENCE`，不能将码表全量值再写进本地库。

## 金融许可证号

金融许可证号是 `ENCODING_RULE`，不是一个 `CODE_DOMAIN` 文本：

- 固定长度 15，字符族为大写字母和数字。
- 分段为 `1-1` 机构类型、`2-5` 机构、`6-6` 组织类别、`7-7` 发证机关、`8-11` 地址、`12-15` 顺序。
- 机构类型、组织类别、发证机关的可选项由 V3 输出为带分段 ID 的 `local_code_set/local_code_value`。
- 地址段写 `CODE_TABLE_REFERENCE`；若审阅绑定指向 `CD000003`，保留该绑定来源和版本/适配状态，不替换为无证据的 GB/T 版本结论。
